1. Introduction

This manual explains how an end user installs RepoTrace and uses it. RepoTrace is a local system for a Python project. It reads the source and, when the folder is a Git repository, the saved history. It shows where code lives, which functions call which, what a chosen change could affect, and which existing tests are connected to that change.

The system does not upload the project, does not edit the repository, and does not run the project’s code or its tests. A result that lists nothing found is a report that nothing was found. It is not a statement that the change is safe.

The manual is written for a person who has the project folder on their own computer and wants to open it, compare two versions, and read the review. It covers installation, the order of use, the messages shown when something cannot be done, and the help already placed on the screens.

2. Installation and starting the system

2.1 What is required

The computer needs Python 3.9 or newer [2]. Git is required only when two versions are compared [3]. No other package is installed. The project folder of RepoTrace itself is the folder that contains repotrace/ and RepoTrace.command.

2.2 Starting the guided screens

The guided screens are the screens this manual describes. Open a terminal, move into the RepoTrace folder, and run:

python3 -m repotrace --lab

The browser opens a page on this computer only. The address looks like http://127.0.0.1:58510/lab. The port can differ each time the system starts. The first screen is Open a project.

To place a folder in the path box before the page opens, pass the folder:

python3 -m repotrace --lab "/path/to/your/project"

2.3 Stopping the system

Leave the terminal window open while the browser is in use. Press Ctrl+C in that terminal, or close the terminal, to stop RepoTrace. Closing the browser page stops the person from reading the result. It does not by itself stop the program until the terminal is stopped.

2.4 The earlier screen

Double-clicking RepoTrace.command, or running python3 -m repotrace with no flag, opens the earlier screen rather than the guided screens. That screen has its own example gallery. This manual does not repeat that gallery. Use the flag --lab when the guided screens are wanted.

3. Using the system

3.1 Open a project

Type the path of a folder that contains Python files, or press Browse… on a Mac, and then press Open. Folders opened before are listed under the form and can be opened from those cards.

Explore without comparing reads the working folder and does not ask for two versions. Use it when the folder has no Git history, or when the map of the current files is enough. Git is required only for a comparison of two saved versions.

The map and the source on screen are the snapshot that was read. If files are edited after that, open the project again. RepoTrace does not watch the folder.

3.2 Choose two versions

When the folder is a Git repository and at least two commits are found, the next screen is Choose what to compare. Two menus are shown.

Table 1. The two version menus
MenuMeaning when Reverse is No
Older version, marked StartThe version before the change.
Newer version, marked EndThe version after the change.

Only explore the map turns the comparison off. Analyse starts the comparison. The two chosen versions must be different. Unsaved edits in the working folder are not part of the comparison. The map can still show the working folder. The comparison uses saved commits only.

3.3 Reverse a comparison

Under the two menus, Reverse this change? has the answers No and Yes. No reads from the older version to the newer version, which is the direction in which the change was made. Yes reads the same two versions in the opposite direction, from the newer version to the older version. Lines that the later version added are then shown as removed, and lines it removed are shown as added. The sentence under the control states the direction before Analyse is pressed. The round swap button switches between No and Yes. The Git repository is not modified.

After a review is open, the switch Reverse this change asks for the same pair again with the opposite answer. A banner states when the review on screen is the reversed one. Turning the switch again returns to the first direction. Each direction is a new read of the same two commits.

3.4 While the system reads

The page keeps one list and moves the highlight down it. The steps are: check the project; map the working folder; read the older version; read the newer version; compare the two versions; find what could be affected; prepare the screens. On a reversed run, the reading steps name the newer version as the start and the older version as the end. A commit identifier under a step is a note about the step that is running. It is not another step. The clock shows the time elapsed. A finished step shows how long it took.

Cancel stops at the end of the step that is running and returns to the previous screen. Nothing in the repository is changed.

3.5 The workspace

After the read finishes, the workspace has five sections. On a wide window they are listed on the left. On a phone they are a bar along the bottom: Start, Review, Map, Files, and Settings.

Table 2. Workspace sections
SectionUse
StartThe comparison in one paragraph, the counts, and the ways into the review, the tests, and the map.
Check a changeThe review. When only one comparison was run, this opens that review.
Explore the projectThe map of folders, files, functions, and recorded calls.
File listThe same project as folders, then files, then functions, without the graph.
SettingsAppearance, local Git status, export, and running the comparison again.

Back, or Alt+Left arrow, returns to the previous view. Find code, or Command+K on a Mac and Ctrl+K on Windows and Linux, opens search. The forward slash key does the same when the cursor is not in a text field.

3.6 Check a change

The title of the review is the commit message of the change being read. Start and End name the two versions in the direction of this run. The counts are definitions changed, places to inspect, and tests listed. A count of zero connected tests is marked, because a missing test is a gap in the report.

Run this comparison again repeats the saved pair on this computer. It does not change Git and it does not run tests.

What to check lists the places the comparison flagged, with the line that made each one matter. A comparison can also have changed definitions and no flagged concern. The absence of a flag is not a statement that the change is safe to merge.

Changed code lists each changed definition. A line that begins with a plus sign was added. A line that begins with a minus sign was removed. Colour is a second mark, not the only mark. A removed definition is shown from the older version. A rename pairing is evidence from the comparison. It is not a guarantee that the behaviour is unchanged.

Related tests lists tests connected to the change by following recorded calls, including unittest setUp hooks. A test connected before the change and not followable after it is reported as a path that was lost. A test that reaches the code only through a pytest fixture can be missing, because those fixtures are not all followed. The command beside a test is copied to the clipboard. It is not executed. The list is a starting point. Tests that sit outside the list are counted. Their absence from the short list is not permission to skip the rest of the suite.

Limits and history states what this review cannot establish. History lists files that were edited in the same commits as a changed file. That is a correlation. It is not a call, and it is not a prediction that the files must change together.

3.7 Recommendations

The Recommendations tab reads the review that is already on screen. Each item names a definition, a file, or a test, and gives the recommendation, the reasoning, the evidence, the expected impact, a priority, a confidence, how to carry it out, what is required first, the risks, and a next action.

Table 3. Recommendation levels
LevelMeaning
1, ImmediateA concern, a test whose path exists only in the older version, a removed test, or a changed definition with no connected test.
2, AnalyticalFiles edited together in the saved history. This is correlation, not a cause.
3, PredictiveNot shown. The system has no probability model, so it does not invent a forecast.
4, StrategicAt most one choice between two actions the review already lists.

Confidence is high when the link is written in the source, medium when one step is an assumption, and low when the only support is history. There is no numeric score.

Evidence, Explain, and Action plan open those fields. The main button follows the next action: another tab of the review, the function on the map, or a copied test command. Compare places two items side by side. Save, Mark completed, and Dismiss are stored in this browser for this folder and this pair of versions. They are not uploaded. Show dismissed brings hidden items back. Ask a follow-up searches the words of these items. The page states that the search is not an AI answer. If no words match, the page says so. If no item met the evidence rules, the list is left empty.

3.8 Explore the project

Explore opens the map. On a wide window the controls, the graph, and the detail sit side by side. When the window is too narrow for three columns, the detail moves under the graph. On a phone the regions stack. The side list eases to icons so the map can use the width.

Physical groups the code by folder. Logical groups it by recorded calls. Conceptual is marked experimental. Its topics are guessed from calls and from common words, and they are often wrong. Treat that view as a guess.

Sure links, maybe links, and test code can be shown or hidden. Test code stays hidden until it is requested. Click a name to read it. The lists beside the graph carry the same connections, so the picture is not the only way through. Explore walks the working folder. Review a change marks what the current comparison changed. Search matches words in names, paths, comments, and code. It is not an AI answer.

3.9 Files, search, and the keyboard

File list opens folders, then files, then the functions in a file. A function page shows its source, what calls it, and what it calls. Possible links and Test code filter that page. A missing connection is recorded as missing. It is not proof that nothing calls the function.

Table 4. Keyboard
KeyAction
Command+K, or Ctrl+KFind code
/, when not typing in a fieldFind code
Alt+Left arrowBack
EscLeave a field, then go back

3.10 Settings, export, and running again

Appearance offers twelve editor themes. Pointing at a card previews it. Clicking a card saves it on this computer for the next time the page opens. GitHub Light and Solarized Light are the light themes. The others are dark.

Integrations shows the only Git connection, which is the folder that was opened: the branch, whether the working tree has uncommitted changes, HEAD, and how many recent commits were listed. Refresh local Git reads that status again. There is no separate disconnect action. Closing the page is what stops the read.

Export review JSON and Export review CSV download the review already on screen, including changed definitions, concerns, tests, and recommendations. The file is built in the browser. Nothing is uploaded. GitHub, GitLab, Bitbucket, Slack, and the other hosted services named on that screen are not connected. The system has no sign-in for them, because sending the repository to those services would take the code off this computer.

4. Error handling and reporting

RepoTrace reports a problem on the page that was in use. It does not send the message, the path, or the source to another computer. The person corrects the cause and tries again, or goes back. Table 5 lists the situations an end user meets.

Table 5. What the screen reports, and what to do
SituationWhat is reportedWhat to do
The folder path is empty or cannot be openedThe message returned for that request, on the open screenType a folder that exists on this computer, or use Browse.
The same commit is chosen twiceChoose two different versions, or tick “Only explore the map”.Pick another version, or explore the map only.
The analysis cannot finish“The analysis failed,” with the message, and a way back to choosing a projectRead the message. Typical causes are a missing folder or a Git error. Start again from Open a project.
The person stops a readThe progress screen closes and the previous screen returnsNo repair is required. The repository was not changed.
The folder is not a Git repository“Not a Git repository” on Settings, after Refresh local GitExplore without comparing. A comparison needs saved commits.
There is no review to export“There is no review to export.”Run a comparison first. Export stays disabled until a review exists.
A test command cannot be copied“Copy unavailable here. Select the visible command and copy it.”Select the command on the page and copy it with the browser.
A screen cannot be drawn“This page could not be drawn.”Use Back, or Go to Start. The project was not changed.
A comparison cannot be reversed from the current page“This comparison cannot be reversed from here.”Open a live review that still has the chosen pair. A saved prototype page has no folder to re-read.

If the browser shows that the page cannot be reached, the terminal that started RepoTrace has been closed or the address is from an older run. Start the system again with section 2.2 and use the address printed in the terminal.

5. Help frames

Help is placed on the screens themselves. There is no separate help site. Table 6 names each help frame and what the user should take from it.

Table 6. Help frames
WhereWhat it tells the user
What works here?, at the bottom of the side list, and the status line “Static analysis · not runtime proof”The dialog “Real evidence, with its limits.” Search is word search. A sure link is written in the code. A maybe link depends on an assumption. Neither proves that the code runs. Commands are copied and are not executed. History is not a dependency. A missing link is not proof of safety.
The sentence under Reverse this change?Which direction the next read will use, and that Git will not be modified.
The banner “This review is reversed.”The review runs backwards. Added and removed lines are swapped relative to the later version. The repository was not changed.
The note on RecommendationsWhat each level means, that level 3 is omitted because there is no probability model, and that dismiss, save, and completed stay in this browser.
Empty recommendation list“No recommendation met the evidence rules.” The list is not filled with general advice.
Conceptual, marked EXPERIMENTALThe topic groups are a guess and are often wrong.
Limits and historyWhat the review cannot establish, beside the history counts.
Integrations, last paragraphHosted services are not connected, and the reason is stated on the page.

6. How to read the results

Table 7. Marks used on the screens
MarkMeaning
SureThe call is written in the code.
MaybeOne step depends on an assumption. A call on self can be overridden by a subclass, so it stays maybe.
Old version onlyThe link was recorded in the older version and not in the newer one.
Plus and minus at the start of a diff lineAdded text and removed text.
Connected only beforeA test path that can be followed in the older version and not in the newer one.
Untraced callsCalls inside a changed definition that could not be followed. This is a hole in the map, not proof that no call exists.

When a page is quiet, read Limits and history before deciding what to do next. Then run the tests that were chosen. RepoTrace does not run them.
