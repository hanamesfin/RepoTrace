USER MANUAL · GUIDED SCREENS

Find what a change left behind.

RepoTrace reads a Python project on your computer, without running it, and shows where a change could matter: the line to inspect, the functions that still depend on it, and the tests connected to it.

  • Stays here Nothing is uploaded. The app listens only on this computer.
  • Reads, never edits Git history is read. The repository is not changed, and your code is not executed.
  • A quiet page is not a verdict “Nothing found” means nothing was found. It does not mean the change is safe.

01 Start here

One pass through the guided screens is enough to learn the product. The order is the order of the work:

  1. Open a folder of Python files.
  2. Pick two saved versions, or skip the comparison and explore the folder as it is.
  3. Read the review: what changed, what still depends on it, which tests are connected.
  4. Open one function and follow one connection.
  5. Copy a test command if you want to run it yourself. RepoTrace does not run it.

You need Python 3.9 or newer, and Git if you want to compare versions. There is nothing else to install.

02 Open the app

In a terminal, from the RepoTrace folder:

python3 -m repotrace --lab

The browser opens a page that begins with Open a project. The address is on this computer only, something like http://127.0.0.1:58510/lab. Leave the terminal open. Closing it, or pressing Ctrl C, stops the app.

Two screens live in this project. --lab is the guided screen this manual describes. Double-clicking RepoTrace.command, or running python3 -m repotrace with no flag, opens the earlier screen. That screen, and the built-in examples, are in GUIDE.md.

To open a folder immediately, pass its path:

python3 -m repotrace --lab "/path/to/your/project"

03 Open a project

Type the folder path, or press Browse… on a Mac, then Open. Recent folders appear as cards under the form. A folder does not need Git if you only want the map.

Explore without comparing skips version choice and reads the working folder. Use it when there is no history yet, or when you only want to walk the code.

The map is a snapshot. The code on screen is the code that was read. If you edit a file afterwards, open the project again to refresh. RepoTrace does not watch the folder.

04 Choose what to compare

After a Git project opens, you see how many commits were found. Two menus hold the versions.

Reverse this change?

No reads from the older version to the newer one, the way the change happened. Yes reads the same two versions backwards, from the newer one to the older one. Added lines then show as removed, and removed lines show as added. Git is not modified. The sentence under the Yes / No control says which way the run will go.

Only explore the map turns the comparison off and reads the working folder. Analyse starts the comparison. The two versions must be different.

05 While it reads

The page stays put and moves a highlight down one list. A large project can take a minute. The steps, in order, are:

  1. Check the project
  2. Map the working folder
  3. Read the older version
  4. Read the newer version
  5. Compare the two versions
  6. Find what could be affected
  7. Prepare the screens

On a reversed run, the two reading steps say that the newer version is the start and the older version is the end. A commit id under a step is a note about the step that is running. It is not an extra step. The clock at the top counts elapsed time, and a finished step shows how long it took.

Cancel stops at the end of the step that is running. Nothing in the repository is changed. You return to the screen you came from.

07 Check a change

The title is the commit message of the change. Under it, Start and End name the two versions in the direction of this run. The counts beside the title are definitions changed, places to inspect, and tests listed. A count of zero connected tests is marked, because a missing test is a gap, not a clean result.

The switch Reverse this change reads the same pair the other way. Turning it on starts a new read. Turning it on again returns to the original direction. A banner says when the review you are looking at is the reversed one.

Run this comparison again repeats the saved pair on this computer. It does not change Git and it does not run tests.

What to check

The places the comparison flagged, each with the line that made it matter. Open the evidence when you want the recorded reason. A place with no flag still has a changed definition on the next tab. “No flagged concerns” does not mean safe to merge.

Changed code

Each changed definition can be opened. A line that starts with + was added. A line that starts with − was removed. The colour is a second mark, not the only one. A removed definition is shown from the older version. A rename pairing is evidence from the comparison, not a guarantee that the behavior is the same.

Related tests

Tests connected to the change by following recorded calls, including setUp hooks. A test that was connected before the change and cannot be followed after it is listed as a path that was lost. Pytest fixtures are not all followed, so a test that reaches the function only through a fixture can be missing. The command next to a test is copied. Nothing is executed. The list is a starting point. Tests outside the list are counted, and they are not permission to skip the rest of the suite.

Limits and history

Limits are what this review cannot establish. History lists files edited in the same commits as a changed file. That is a correlation. It is not a call, and it is not a prediction that both files must change together.

08 Recommendations

The Recommendations tab is a reading of the review you already have. Each item names a specific definition, file, or test, and says why it is there. The fields are the recommendation, the reasoning, the evidence, the impact you can expect, a priority, a confidence, how to do it, what has to come first, the risks, and a next action.

LevelWhat it means
1 ImmediateA concern, a test whose path exists only in the older version, a removed test, or a changed definition with no connected test.
2 AnalyticalFiles edited together in the saved history. Correlation, not a cause.
3 PredictiveNot shown. There is no probability model, so a forecast would be invented.
4 StrategicAt most one choice between two actions the review already lists.

Confidence is high when the link is written in the source, medium when it depends on an assumption, and low when it is only history. There is no numeric score.

On an item you can open Evidence, Explain, and Action plan. The primary button follows the next action: another tab, the function on the map, or a copied test command. Compare puts two items side by side. Save, Mark completed, and Dismiss stay in this browser, for this folder and this pair of versions. They are not uploaded. Show dismissed brings hidden items back.

Ask a follow-up searches the words in these recommendations. A match says it is not an AI answer. If nothing matches, the page says so.

An empty list is allowed. If no recommendation met the evidence rules, the page says that. It does not fill the list with general advice.

09 Explore the project

Explore opens the map across the workspace. On a wide window you get three regions: the controls, the graph, and the detail. When the window is narrower than the graph needs, the detail moves underneath, and on a phone the regions stack. The side rail eases to icons so the map can use the width.

Three views

  • Physical. Where the code lives, grouped by folder.
  • Logical. What calls what, grouped by connections.
  • Conceptual. Marked experimental. Topics guessed from calls and common words. Often wrong. Treat it as a guess.

Show or hide Sure links, Maybe links, and All test code. Tests stay hidden until you ask for them. Click a name to read it. The lists beside the graph carry the same connections, so the picture is not the only way through.

Explore walks the working folder. Review a change rings what this comparison changed, on that comparison’s graph. Search at the top finds a function or asks with words from names, paths, comments, and code. It is word search, not an AI answer. Recent searches stay on this computer until you clear them.

10 Find, files, and the keyboard

File list is the project as folders, then files, then the functions inside a file. Open a function for its source, the functions that call it, and the functions it calls. Possible links and Test code are filters on that page. A missing next connection is recorded as missing. It is not proof that nothing calls the function.

11 Settings

Appearance

Twelve editor themes. Hover or focus a card to preview it. Click to save it on this computer. The choice is applied the next time the page opens. GitHub Light and Solarized Light are the light themes. The others are dark.

Integrations

The only Git connection is the folder you opened. The page shows the branch, whether the working tree has uncommitted changes, HEAD, and how many recent commits were listed. Refresh local Git reads that status again. If the folder is not a Git repository, the page says so.

Export review JSON and Export review CSV download the review that is already on screen: changed definitions, concerns, tests, and recommendations. The file is built in the browser. Nothing is uploaded.

Cloud services are not connected. GitHub, GitLab, Bitbucket, Slack, and the other listed services have no sign-in here. Sending the repository to them would leave this computer. Closing the page is what stops the read.

Run this comparison again

The same control as on the review. It repeats the saved base and head. It does not schedule anything, and it does not run in the background after you close the page.

12 How to read what you see

What you seeWhat it means
SureThe call is written in the code.
MaybeOne step depends on an assumption. A method on self can be overridden, so it stays maybe.
Old version onlyThe link was recorded in the older version and not in the newer one.
+ and −Added text and removed text in the diff.
Connected only beforeA test path RepoTrace can follow in the older version and not in the newer one.
Untraced callsCalls inside a changed definition that could not be followed. A hole in the map, not proof that nothing is there.

Search matches words. A connection is a recorded link. Neither one proves that the code runs.

13 What this cannot tell you

  • It cannot prove a change is safe, and it will not say that it is.
  • It cannot see every call Python decides at run time. A missing link is a hole, not an absence.
  • A suggested test is not proof of coverage, and a test that is missing from the list may still reach the change through a fixture.
  • History is a hint about files edited together. It is not a dependency.
  • Recommendations are rules over this review. They are not a forecast and not a model score.
  • There is no sign-in to GitHub or to chat and issue trackers. Analysis stays on this computer.

When the page is quiet, read the Limits tab before you decide. Then run the tests you choose. RepoTrace will not run them for you.

14 The other doors

The earlier screen opens with python3 -m repotrace. It has the example gallery, the outline, and the picture of callers. How to run each example, and what you should see, is GUIDE.md.

From the terminal, without either screen:

python3 -m repotrace change REPO --base HEAD~1 --head HEAD
python3 -m repotrace map FOLDER --output map.json
python3 -m repotrace help

change writes what the last commit could affect. --include-possible keeps the maybe links. --max-tests changes how many tests are ranked first. The ranking is a starting point. It does not estimate which test will fail.

Written for the guided screens in this folder. The rules it follows are the project guide and the handbook: say what was read, keep a guess labelled as a guess, and never call a change safe.
